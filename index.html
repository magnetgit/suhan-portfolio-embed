완료 · 인증과 데이터 구조

  • Django 비밀번호 해시를 가입·로그인·비밀번호 찾기·탈퇴에 적용하고, 기존 평문 계정의 첫 로그인 시 해시 전환을 구성했습니다.
  • 회원 아이디와 이메일을 분리하고, 성별·나이대는 동의한 경우에만 저장하도록 변경했습니다.
  • 모델을 Django 마이그레이션 관리로 전환하고, 카테고리 예산·리뷰·도움돼요 테이블과 관리자 화면을 정비했습니다.
  • 리뷰 목록 API와 여러 장소의 평균 별점·리뷰 수를 한 번에 반환하는 요약 API를 구현해 main에 병합했습니다.
  • 일정 직접 추가와 채팅 적용 흐름에서 카카오 장소 ID를 저장하도록 변경했습니다. main 병합 후 서버에도 반영했습니다.
  • 최신 리뷰를 LLM으로 읽어 장소별 키워드와 한 줄 요약을 만드는 리뷰 키워드 API를 구현했습니다. 결과를 저장해 두고 리뷰 수가 바뀔 때만 다시 요약합니다.
  • 채팅에서 담은 장소가 숙소 도착 뒤에 붙거나 다른 날 자동 일정에 중복되던 문제를 고쳐, 숙소 앞에 배치하고 순서·시간을 다시 계산하도록 했습니다.
  • 채팅 추천 카드 순서에 같은 성별·나이대 회원의 리뷰 평점을 섞고(둘 중 하나만 있어도 적용), 여행 컨셉과 리뷰 키워드가 겹치면 가산점을 주는 맞춤 추천 점수를 구현해 main에 병합하고 서버에 반영했습니다.
  • 리뷰 게시판에 장소·카테고리·지역·태그별 분류 보기와 추천순·최신순·별점순 정렬, 번호 페이지를 집계 쿼리로 구현해 서버에 반영했습니다.
  • 리뷰·관광지 소개글 검색(RAG)에 쓸 임베딩 벡터 테이블과 임베딩 생성·저장·유사도 검색 함수를 만들어 팀원이 같은 함수를 쓰도록 공유했습니다.
  • 외부 API 결과 캐시를 DB 테이블에 저장하도록 바꿔, 카카오 대중교통 경로처럼 반복 호출되는 결과를 서버 재시작 후에도 재사용합니다.
  • 장소별 리뷰를 임베딩해 저장하고, 리뷰 내용이 비슷한 장소를 코사인 유사도로 찾아 주는 리뷰 RAG API를 구현해 서버에 반영했습니다.
  • 회원이 예산 금액을 넣거나 고치거나 지우면 DB 트리거가 변경 내역을 자동으로 기록하는 테이블과 조회 API를 만들어 서버에 반영했습니다.
  • 축제 카드에 1인 요금 × 인원 예상 요금을 붙이고, 같은 날 같은 숙소가 두 번 나오면 숙박비를 한 번만 계산하도록 예산 계산을 고쳐 서버에 반영했습니다.
  • 일정 시간을 다시 계산할 때 대중교통 구간은 카카오 대중교통 경로 시간을 쓰도록 바꾸고, 여행 삭제에 로그인·작성자 확인을 넣어 다른 회원의 여행을 지울 수 없게 했습니다. 모두 서버에 반영했습니다.
  • 리뷰 키워드 요약을 GPT와 로컬 공개 모델(qwen3·EXAONE·Llama)로 같은 조건에서 비교하는 명령과 비교표를 만들고, 결과를 바탕으로 요약 프롬프트와 문장형 키워드 거르기를 보완해 서버에 반영했습니다.
  • 일정을 만들 때 담아 둔 장소를 운영시간 안 첫 자리에 넣고, 점심(12~13시)·저녁(18~19시) 시간대를 지키도록 장소 종류별 체류 시간 범위 안에서 앞뒤 일정을 늘리고 줄이게 했습니다. 서버에 반영했습니다.
  • Streamlit으로 운영 대시보드를 만들어 회원·여행·리뷰·예산 변경 기록의 월별·연도별 증감, 날짜별 추이, 성별·나이대별 선호 장소, 장소별 비용을 보여 주고, 서버에 별도 서비스와 Nginx 비밀번호 보호로 배포했습니다.
  • 여행지까지 가는 방법(KTX·환승·고속버스·비행기·배·자차·렌터카)을 공공데이터 시간표 기준으로 가격·시간 비교하고, 고르면 첫날 출발점·일정·지도·교통 예산에 바로 반영하는 기능을 구현해 main에 병합하고 서버에 반영했습니다.
  • 리뷰 게시판 분류 기준에 나이대·성별을 추가하고, 체크인 시각 저장을 하루 계획과 맞추며 일정 삭제에 로그인·작성자 확인을 넣었습니다. 모두 서버에 반영했습니다.
  • 여행지까지 가는 길·돌아오는 길 구간을 첫날과 마지막 날에만 보여 주고 접었다 펼 수 있게 했습니다. 접은 상태는 브라우저에 기억합니다. 서버에 반영했습니다.
  • 채팅 에이전트(LLM 호출·도구 호출·추천 카드)를 Django 밖의 FastAPI 서버 프로세스로 분리했습니다. 응답 모양과 기존 함수는 그대로 두고, 설정 한 줄로 예전 방식과 전환되게 했습니다. 서버에 별도 서비스로 띄우고 토큰 검사까지 적용했습니다.
  • 2박 이상 여행에서 숙소를 밤마다 고르거나 연박으로 한 번에 넣을 수 있게 하고, 일정을 끌었다가 제자리에 놓으면 이동 구간 정보가 엉뚱한 자리에 남던 화면 문제를 고쳤습니다. 서버에 반영했습니다.
  • 화면 언어 바꾸기(한국어·영어·일본어·중국어)를 넣었습니다. 기존 템플릿은 고치지 않고 미들웨어가 모든 화면에 번역 스크립트와 사전을 붙이며, 장소 이름·리뷰처럼 사전에 없는 글은 LLM으로 번역해 DB 테이블에 저장해 두고 다시 씁니다. 번역 요청에는 횟수·길이 제한을 두었습니다. main 병합 후 서버에 반영했습니다.
  • 휴대폰 화면을 보완했습니다. 홈의 폰 미리보기에서 휴대폰·폴더블·태블릿 12종을 고를 수 있게 하고, 카메라·홈 막대 자리를 피하는 안전 영역과 버튼 글자가 넘치거나 두 줄이 되면 한 줄로 맞추는 스크립트를 모든 화면에 적용했습니다. 서버에 반영했습니다.

완료 · AWS 배포와 문제 해결

EC2의 Nginx → Gunicorn → Django와 MariaDB를 구성하고 HTTPS 인증서와 요금 알림을 설정했습니다. 서버의 테이블 이름 대소문자 차이로 저장이 실패하던 문제를 소문자 통일로 해결했습니다.

운영 모드에서도 MariaDB를 쓰도록 DB 설정을 정리하고 서버를 운영 설정으로 전환했습니다. 11월 12일 기록 기준 팀 main 변경(PR #150)까지 서버에 배포하고 서비스 응답을 확인했습니다. 배포는 main 병합 후 수동 스크립트로 진행하며, 스크립트가 사이트·운영 대시보드·AI 서버를 함께 다시 시작하고 응답을 확인합니다. 배포 직전 DB 백업과 매일 자동 백업(14일 보관)을 구성했습니다. 관광지 소개글 검색용 데이터는 외부 API 하루 사용량을 넘지 않도록 매일 밤 나눠서 넣는 예약 작업으로 채우고 있습니다.

완료 · 비밀번호 찾기와 시연 데이터

비밀번호 찾기에 이메일 인증 코드(6자리, 10분, 5회 제한)를 확인하는 서버 쪽 구현을 main에 병합하고, 서버 전용 메일 계정으로 실제 메일 발송을 확인했습니다. 시연용 데모 회원·여행·리뷰 데이터는 2020년부터 여행지 15곳, 다양한 출발지와 이동 방법으로 넓혀 서버에도 적용했습니다.

진행 · 다음 작업

11월 19일 기능 동결을 앞두고 배포 서버에서 가입부터 일정 생성·비용·리뷰까지 전체 흐름을 점검하고 있으며, 팀 밖 사용자에게 서비스를 써 보게 하고 받은 의견을 반영할 예정입니다. AI 서버는 현재 프로세스 분리 단계이며, 서버를 따로 두는 것은 다음 단계로 남겨 두었습니다.

01. 어떻게 진행하나요?

  1. Enter로 시작

    약 2초의 라운드 준비 화면 후 시작합니다. 각 라운드의 제한시간은 10초로 다시 설정됩니다.

  2. 왼쪽부터 차례로 입력

    무작위로 만들어진 3~8개의 화살표를 WASD 또는 방향키로 입력합니다. W=↑, A=←, S=↓, D=→입니다.

  3. 완성하면 점수와 시간 획득

    한 문제를 모두 맞히면 점수를 얻고 시간이 1초 늘어납니다. 남은 시간은 최대 10초이며, 다음 문제로 바로 넘어갑니다.

  4. 실수하면 같은 문제를 처음부터

    틀린 입력은 현재 문제의 입력 위치를 초기화합니다. 직접적인 점수 차감이나 추가 시간 차감은 없지만, 타이머는 계속 흐르고 해당 라운드의 완벽 보너스를 잃습니다.

  5. 라운드를 클리어하며 계속 도전

    1라운드는 6문제, 2라운드는 7문제처럼 라운드마다 1문제씩 늘어납니다(라운드 번호 + 5). 결과 화면을 약 3초간 보여준 뒤 다음 준비 화면으로 넘어갑니다. 시간이 0이 되면 게임이 끝납니다.

02. 화면에는 무엇을 보여주나요?

  • 왼쪽 위: 현재 라운드 번호
  • 오른쪽 위: 지금까지 누적한 점수
  • 가운데: 현재 문제의 화살표. 입력 전은 흰색, 맞힌 화살표는 초록색으로 표시합니다.
  • 오답 피드백: 화살표 전체가 빨갛게 변하며 좌우로 흔들린 뒤 흰색으로 돌아옵니다. 입력·정답·오답에는 효과음도 재생됩니다.
  • 아래: 소수점 한 자리의 남은 시간과 시간 막대. 2초 이하가 되면 시간·막대·점수·라운드를 빨간색으로 바꿔 경고합니다.

03. 점수는 어떻게 계산하나요?

문제 점수는 완성 즉시 누적하고, 라운드를 성공했을 때만 세 가지 보너스를 더합니다.

항목계산 규칙적용 시점
문제 점수완성한 문제의 화살표 개수 × 5점
3개는 15점, 8개는 40점		문제 전체 완성 시
라운드 보너스현재 라운드 번호 × 25점라운드 클리어 시
시간 보너스남은 시간 × 10의 소수점 이하 버림
코드: int(time_left * 10)		마지막 문제의 +1초 반영 후
완벽 보너스해당 라운드에서 오답이 없으면 100점, 있으면 0점라운드 클리어 시
계산 예시 · 1라운드

6문제의 화살표 수가 3·4·5·6·7·8개라면 문제 점수는 33 × 5 = 165점입니다. 마지막 문제의 시간 회복까지 반영한 내부 남은 시간이 정확히 6.5초이고 오답이 없었다면:

165 + 25 + 65 + 100 = 355점

결과 화면에는 문제 점수, 라운드 보너스, 시간 보너스, 완벽 보너스, 총 획득, 누적 점수를 차례로 표시합니다. 이미 누적한 문제 점수를 다시 더하지는 않습니다.

시간 보너스는 화면에서 반올림해 표시한 숫자가 아니라 내부 시간값으로 계산합니다. 시간 초과 시에는 완성한 문제의 점수는 유지되지만, 실패한 라운드의 보너스와 미완성 문제 점수는 받지 못합니다.

04. 게임 종료와 랭킹

최종 점수를 약 3초간 보여준 뒤, A~Z로 최대 3글자의 이니셜을 입력합니다. Backspace로 지우고 Enter로 저장합니다. 빈 이름은 ‘-’로 기록합니다.

랭킹은 점수 높은 순 → 도달 라운드 높은 순 → 먼저 기록한 순으로 정렬해 JSON 파일에 최대 100건을 보관합니다. 화면에는 순위·이니셜·도달 라운드·점수를 표시하고, 상위 5위 밖의 플레이어 기록은 별도 줄로 보여주도록 구성했습니다. Enter를 누르면 시작 화면으로 돌아갑니다.

05. 구현하며 배운 것

게임 상태를 타이틀·준비·플레이·결과·이니셜·랭킹으로 나누고, 상태에 따라 키 입력을 처리했습니다. Tkinter의 예약 콜백으로 타이머와 화면 전환을 제어하고 Pillow 이미지와 Pygame 효과음을 연결했습니다.

문제 생성, 게임 진행, UI, 타이머, 점수, 사운드, 랭킹을 모듈로 분리했습니다. JSON 기록 저장과 Windows 실행 파일 패키징까지 이어가며 하나의 프로그램을 완성하는 과정을 경험했습니다.

설명 기준: 현재 Mygame2/EXE 소스. Mygame2.zip의 기본 진행·점수 규칙을 함께 확인했으며, 방향키 지원·2초 경고·랭킹은 현재 폴더에 추가된 구현입니다.
